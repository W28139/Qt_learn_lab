## 需求

在 `D:\Qt_\learn_demo\lab03_skeleton\` 新建独立 CMake 工程，实现一个客户端主窗口骨架：

1. 窗口标题 `Lab 03 - Client Skeleton`，初始大小 `900 x 600`，最小 `720 x 480`；
2. `QMainWindow` 结构：
   - 菜单“文件(&F)”：连接（`F5`）、断开（`Shift+F5`）、分隔线、退出（`Ctrl+Q`）；
   - 菜单“帮助(&H)”：关于 Lab 03；
   - 工具栏包含连接/断开两个 action，只显示文字、不可拖动；
   - 状态栏：启动时临时显示“就绪”；右侧永久显示“连接状态”和“端点”两个标签；
3. 中央区为 `QTabWidget`：
   - 第一个标签“连接”，内容是独立的 `ConnectionPage` 类；
   - 第二个标签“实时数据”，放一个居中占位标签“实时数据页将在单元 04 接入。”；
4. `ConnectionPage` 的布局：
   - 左侧一列：`QGroupBox`“服务器”、`QGroupBox`“操作”、底部弹簧；
   - 服务器组用 `QFormLayout`，字段依次为：
     - 主机(&H)：`QLineEdit`，默认 `127.0.0.1`，占位提示“IP 或主机名”，带清除按钮；
     - 端口(&P)：`QSpinBox`，范围 `1～65535`，默认 `9000`；
     - 协议：`QComboBox`，`TCP` / `UDP`；
     - 会话名称：`QLineEdit`，默认 `default`，最大 32 字符；
     - 自动重连：`QCheckBox`“断线后自动重连”，默认不勾选；
   - 操作组：提示 `QLabel`（自动换行）+ 连接/断开按钮一行；
   - 右侧：`QGroupBox`“会话日志”，内部只读 `QPlainTextEdit`，最多保留 500 行；
   - 页面外边距 12、间距 12；日志区占据所有多余空间；
5. 连接流程（用 `QTimer` 模拟，不接网络）：
   - 点击“连接”时先校验：主机、会话名称去空格后不能为空；失败用 `QMessageBox::warning` 提示并把焦点放回对应输入框，状态保持“未连接”；
   - 校验通过：状态变 `Connecting`，日志记录“正在连接 主机:端口 (协议)，会话名称…，自动重连…”，禁用参数输入和连接按钮，启用断开按钮，启动 800ms 单次定时器；
   - 定时器到期：状态变 `Connected`，日志记录“连接成功”，状态栏端点显示 `主机:端口 (协议)`；
   - 点击“断开”：连接中则取消定时器并记“已取消连接”；已连接则记“已断开连接”；最终状态回到 `Disconnected`；
   - 断开按钮在 `Connecting` 和 `Connected` 下都可用；
6. 所有状态变化必须通过一个 `setState()` + `updateUi()`，并发出 `stateChanged` 信号让主窗口更新 action 可用性、状态栏永久标签和临时消息；
7. “关于”使用 `QMessageBox::about`，显示应用名、版本和“Qt 版本：…”（`qVersion()`）；
8. 点窗口关闭（×/Alt+F4）或菜单“退出”时，若状态不是 `Disconnected`，用 `QMessageBox::question` 确认；选“否”则窗口不关闭；
9. 构建 0 warning。

## 步骤

1. 按单元 00/01 的方式建工程，`CMakeLists.txt` 只依赖 `Widgets`；
2. 先写 `ConnectionPage` 的静态界面：两个 `QGroupBox` + 日志区，确认布局比例正确；
3. 加入 `State` 枚举、`setState()`、`updateUi()`，先把三态的按钮/输入框行为调对；
4. 加入 `QTimer` 模拟连接与取消；
5. 再写 `MainWindow`：菜单、工具栏、`QAction`、`QTabWidget`、状态栏；
6. 接上 `stateChanged` 信号，确认菜单、工具栏、状态栏三处同步；
7. 加关于对话框和 `closeEvent`；
8. 构建并逐项过验收清单。

## 运行后应该看到

- 启动时状态栏临时显示“就绪”，右侧永久标签为“未连接 / --”；
- 按 `F5` 或点菜单/工具栏“连接”：输入框变灰、连接按钮变灰、断开按钮可用，日志出现“正在连接…”，状态显示“连接中…”；
- 约 800ms 后自动变“已连接”，端点出现在状态栏右侧；
- 连接中立即点“断开”，日志显示“已取消连接”，不会在 800ms 后又变成已连接；
- 已连接时按 `Shift+F5` 能断开；
- 把主机清空再连接，弹出参数错误提示，焦点回到主机输入框；
- 连接中或已连接时点 ×，弹出确认框；选“否”窗口保持打开；
- 切换“实时数据”标签，看到占位文字；
- 拉伸窗口：日志区变宽变高，左侧表单保持合理宽度；缩小窗口时不会把控件压到看不清；
- 菜单打开时，按住 `Alt` 能看到“文件/帮助”的助记符；在连接页按 `Alt+H`、`Alt+P` 能跳到对应字段；
- 构建 0 warning。

## 可选实验（建议至少做两个）

**实验 A：换成 QGridLayout**

把服务器组里的 `QFormLayout` 改成 `QGridLayout`（标签、字段、跨列复选框），比较两者在窗口拉宽时的对齐差异。想一想：如果以后要加“高级选项”折叠行，哪种布局更好维护？

**实验 B：换成 QSplitter**

把页面顶层的 `QHBoxLayout` 换成水平 `QSplitter`，左边是参数面板，右边是日志面板。拖动分隔条，观察最小尺寸限制（提示：给左右面板设 `setMinimumWidth`）。再想一下：`QSplitter` 里的“页面”还需要自己写布局吗？

**实验 C：自定义“关于”对话框**

用 `QDialog` + `QDialogButtonBox` 替换 `QMessageBox::about`，显示应用名、版本、Qt 版本和一个“确定”按钮。然后用 `exec()` 和 `show()` 各跑一次，观察调用点是否被阻塞、对话框是否模态。

**实验 D：故意破坏布局**

临时给日志区设 `setFixedHeight(120)`，再给左侧面板设一个很大的 `setMinimumWidth(600)`。拉伸窗口，观察哪些行为变得不合理，再改回来。记录“固定尺寸”在 DPI 和字体变化下的风险。

**实验 E：扩展状态机**

给 `ConnectionPage` 增加一个 `Error` 状态（例如连接模拟失败），或在自动重连勾选时增加 `Reconnecting`。只允许通过 `setState()` 进入新状态，补全 `updateUi()` 和主窗口的 action 逻辑。体会“加状态时只需要改两处”的好处。

## 思考

1. 为什么 `QMainWindow` 不能直接 `setLayout`？如果硬要这么做会发生什么？
2. 本 Lab 中日志区为什么能跟着窗口变高，而左侧表单不会？stretch 和 `QSizePolicy` 各起了什么作用？
3. 如果把 `QSpinBox` 的 `setRange()` 删掉，端口默认值 9000 会变成什么？为什么？
4. 连接中关窗口并确认退出时，那个 800ms 的定时器会怎样？为什么不会在窗口销毁后触发？
5. 为什么把“读取参数 + 校验”收成 `readParams()`，而不是在 `startConnect()` 里直接读控件？以后接真实网络时这个函数的返回值给谁用？
6. 如果把连接页直接写在 `MainWindow` 里（几百个 `new`），以后想把它复用到设置对话框，代价是什么？
7. 菜单、工具栏、状态栏三处状态不一致，通常是因为哪里写错了？如何从结构上避免？
